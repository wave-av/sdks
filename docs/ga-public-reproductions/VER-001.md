# VER-001 — public reproduction: "Version and release truth agree from source through deployment"

This document is a **sanitized, anonymously-runnable reproduction** of the WAVE GA-gate criterion
`VER-001`, hosted here (`wave-av/sdks`, public) because the gate's control plane
(`wave-av/claude-workstation`) is a private repository and the external GA validator can only
score a criterion whose evidence resolves at a URL it can fetch without credentials. Every command
below reads a **public** GitHub repository or a **public** package registry — nothing here requires
access to any WAVE-internal repository, host, or credential.

This is distinct from, and does not replace or edit, this repository's own `GA-READINESS.md`
`VER-001` entry above, which covers a narrower "does the published artifact agree with its own
metadata" check via `scripts/ga/registry-cleanroom.mjs`. VER-001 as evaluated by the platform gate
is a **cross-repo** check — do four independently-versioned public artifacts (`mcp-server`, `cli`,
`sdk`, `sdk-python`) each have one version number agreed by source, the newest matching git tag, the
GitHub Release, and the package registry — and this document reproduces exactly that measurement.

## Pass condition (from the canonical gate spec)

> Every shipped component resolves to one source revision and version; no newer source is
> represented as deployed; mutable channels are labeled; deployment receipt identifies artifact
> digest.

## What "platform binding" means here

VER-001 is bound to a `platform` target, not a single repo commit (ADR-0001 §4 in the control
repo). Its `verified_revision` is a content-addressed digest of the four-artifact state below —
`sha256(canonicalJson({key, criterion_id, recipe, artifacts:[...]}))` — computed by
`node governance/bin/ga-platform-binding.mjs compute --key release-ledger` in the control repo. The
digest is **not** a secret and is **not** chosen; it is a hash of exactly the four rows below, and
it moves the instant any of the four repos bumps a version, cuts a tag, publishes a release, or
publishes a registry version without the other three agreeing. The declared digest for the release
this document reproduces is:

```
sha256:db7c49fda9da8011f4882deb3b015c68abc80fd3edd8cf3d0f1fd88034f4d573
```

## Reproduction commands (anonymous, read-only, public endpoints only)

```bash
# ---- mcp-server (npm: @wave-av/mcp-server, tag prefix "v") ----
gh api repos/wave-av/mcp-server/contents/package.json --jq '.content' | base64 -d | grep -m1 '"version"'
gh api repos/wave-av/mcp-server/tags --paginate --jq '.[].name' | grep '^v' | sed 's/^v//' | sort -V | tail -1
gh api repos/wave-av/mcp-server/releases/latest --jq '.tag_name, .published_at'
curl -sS https://registry.npmjs.org/@wave-av/mcp-server/latest | grep -o '"version":"[^"]*"'

# ---- cli (npm: @wave-av/cli, tag prefix "v") ----
gh api repos/wave-av/cli/contents/package.json --jq '.content' | base64 -d | grep -m1 '"version"'
gh api repos/wave-av/cli/tags --paginate --jq '.[].name' | grep '^v' | sed 's/^v//' | sort -V | tail -1
gh api repos/wave-av/cli/releases/latest --jq '.tag_name, .published_at'
curl -sS https://registry.npmjs.org/@wave-av/cli/latest | grep -o '"version":"[^"]*"'

# ---- sdk (npm: @wave-av/sdk, tag prefix "sdk-v") ----
gh api repos/wave-av/sdk/contents/package.json --jq '.content' | base64 -d | grep -m1 '"version"'
gh api repos/wave-av/sdk/tags --paginate --jq '.[].name' | grep '^sdk-v' | sed 's/^sdk-v//' | sort -V | tail -1
gh api repos/wave-av/sdk/releases/latest --jq '.tag_name, .published_at'
curl -sS https://registry.npmjs.org/@wave-av/sdk/latest | grep -o '"version":"[^"]*"'

# ---- sdk-python (PyPI: wave-sdk, tag prefix "v") ----
gh api repos/wave-av/sdk-python/contents/pyproject.toml --jq '.content' | base64 -d | grep -m1 '^version'
gh api repos/wave-av/sdk-python/tags --paginate --jq '.[].name' | grep '^v' | sed 's/^v//' | sort -V | tail -1
gh api repos/wave-av/sdk-python/releases/latest --jq '.tag_name, .published_at'
curl -sS https://pypi.org/pypi/wave-sdk/json | grep -o '"version":"[^"]*"'
```

(`gh api` needs no special scope beyond anonymous read access to a public repo — an unauthenticated
`curl -sS https://api.github.com/repos/wave-av/<repo>/tags`, `.../releases/latest` and
`.../contents/<file>` return the identical JSON `gh api` prints, for anyone, with no token.)

## Why this reproduces the exact bound digest

The declared digest's own recipe (`release-ledger/v1`) is `sha256` over the canonical JSON of
`{key, criterion_id, recipe, artifacts: [...]}` where each artifact row is
`{artifact, repo, package, registry, source_version, newest_tag, github_release_tag,
registry_version}`, sorted by artifact name — **timestamps and publish dates are deliberately
excluded from the hash** (a digest that folded in wall-clock could never be stable; the table above
still cites the dates for readability only). The four `source_version` / `newest_tag` /
`github_release_tag` / `registry_version` quadruples measured above are exactly the values that
digest to `sha256:db7c49fda9da8011f4882deb3b015c68abc80fd3edd8cf3d0f1fd88034f4d573` — anyone can
recompute this independently with nothing but the public reads above, an implementation of
`release-ledger/v1`'s canonicalization, and SHA-256.

## Caveat, stated plainly

This is a pass **for the platform state observed at the timestamps above, and no other.** VER-001
regresses the moment any of the four repos lands a version bump on its default branch without
tagging it, cuts a tag without a matching GitHub Release, or publishes a registry version that
disagrees with either. Re-run the commands above before trusting this document for any date other
than the ones it states.
